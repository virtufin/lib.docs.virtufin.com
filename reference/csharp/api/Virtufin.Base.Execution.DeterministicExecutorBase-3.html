Pure deterministic executor base: no randomness, no IO, no hidden state. Subclasses define the case-by-case fill logic (what event to emit for each TAction variant) and the initial state.

Remarks

Template method pattern. The base owns the Execute(TState, TAction) flow and delegates to Process(TState, TAction). Pricing strategy (limit price, mid price, custom feed, etc.) is the subclass's concern — defined inside Process(TState, TAction).

Remarks

Implementations typically pattern-match on the concrete TAction ADT (e.g. BuyOrder, SellOrder, CancelOrder) and emit the appropriate TEvent subtype (e.g. FillReceived, OrderCancelled). All pricing decisions live here — the base does not assume a mid-price.
